# Document-defined toolbar solutions

Implemented from the user-selected [Formatting toolbar solutions](https://docs.google.com/document/d/1RRapoQvgYt93Ht-B2GCwZotjMoJUpJOKeOwTIsLu6lk/edit?tab=t.1h9h9a4xip9#heading=h.4straivsyu48) section, read through the Google Docs connector on 2026-09-11. Both the text and four embedded reference images were inspected. This section supersedes the starter's Replace/Stack/Expand interpretation.

| Solution                              | Primary row                                                                    | Opening related settings                                                                              | Entering label editing                                                                                |
| ------------------------------------- | ------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 1. Flat toolbar + popovers            | Individual stateful property controls; stroke color can merge into Stroke      | Stroke, Text, and Alignment replace the row with a sub-toolbar and Back; colors use compact dropdowns | Full text-formatting row: Back, font, size, B/I/U/S, color, horizontal and vertical alignment         |
| 2. Compact toolbar + grouped popovers | Stable compound Stroke, Text and Alignment controls; colors remain independent | One grouped popover at a time                                                                         | Uses Flat's explicit one-line text row by default; a Lab modifier restores the automatic Text popover |
| 3. Inline expansion                   | Compact group controls; stroke color can merge into Stroke                     | Clicking a group inserts highlighted controls into the same row                                       | Automatically expands the Text group in that row                                                      |

The user's subsequent correction applies the Flat navigation pattern to every compound group: Stroke and Alignment use dedicated sub-toolbars with Back, just like Text. Stroke exposes color, pattern, width, and connection direction tools where supported; Alignment exposes horizontal and vertical choices. Simple color/font dropdowns remain available. Opening a color dropdown inside a Flat sub-toolbar preserves that sub-toolbar. Back or Escape returns to object controls (Escape closes an open color dropdown first).

Flat's Text control can also enter formatting-only submode without creating a text caret; Back then returns without changing label content. Grouped and Inline likewise allow formatting without entering label editing. Text mode already exposes alignment directly in its row, so it needs no additional alignment navigation.

## Shared behavior

Grouped Alignment uses a 3×3 position picker. Each cell sets horizontal and vertical alignment together in one undoable edit; mixed selections have no active cell unless both values agree. The collapsed Alignment control uses the corresponding combined-position icon with a tooltip, without a text summary, in all three solutions. Flat and Inline retain their direct axis controls.

- Color buttons show the current color. A 304 px palette opens directly, using eight columns and four rows of neutral, tint, and saturated circular swatches. Fill includes a checkerboard No fill swatch. A blue ring and contrasting checkmark show selection. The custom section shows saved circular swatches followed by a matching circular plus button that opens the native color dialog. Manual color entry stays inside that dialog, with no separate inline input. An eyedropper is available when the browser supports it. The last eight custom colors are saved in this browser for reuse across properties. These palette preferences are separate from experiment JSON.
- Font selection uses four style icons: Normal uses Aa, Classic a baseline A, Compact a narrow A with side guides, and Mono a bracketed A. Grouped shows all four as direct choice buttons inside its text popover, with the current choice highlighted and no nested dropdown. Mixed selections have no active font choice. Flat and Inline use a compact 49 px icon button with a separate mixed icon. It opens a shared styled popover with each class name, style icon, and selected checkmark; there is no native select overlay. Choosing a font or pressing Escape closes only this popover and returns focus to its trigger, preserving the expanded formatting row. The popover follows the same header modifier and positioning rules as color and size. Tooltips and accessible names identify each class.
- Flat and Inline use narrower font selectors alongside a simple size dropdown showing the current value. The size dropdown lists Small, Medium, Large, and Extra large with progressively larger A icons; the custom numeric editor is last. Selecting a preset closes only the dropdown, preserving the Flat sub-toolbar or Inline expansion. Escape and outside clicks also dismiss the dropdown.
- The Grouped text popover keeps font selection on its own row. Size uses one row with four progressively larger A icons for Small (12 px), Medium (16 px), Large (20 px), and Extra large (28 px), followed by a custom numeric editor (8–72 px) whose up/down arrows stay visible. Presets show selection state and named tooltips; non-preset values appear in the custom field.
- Stroke width offers Small (1 px), Medium (2 px), Large (4 px), and Extra large (8 px), shown as distinct line samples in all three behaviors. Zero is no longer offered. Older saved widths remain readable without silently changing diagram styling.
- Interaction Lab includes **Merge stroke color and style**, enabled by default. When enabled, Flat and Inline remove the separate stroke/line color button and place that compact color dropdown inside the Stroke sub-toolbar or inline expansion. Grouped keeps color independent. Switching the modifier off exposes separate color and Stroke buttons in every behavior and removes color from Stroke details. This preference saves locally and travels with experiment JSON.
- Interaction Lab includes **Show popover headers**, enabled by default. Switching it off removes the title and close button from formatting popovers, while retaining accessible group names and the existing trigger/Escape dismissal. This preference saves locally and travels with experiment JSON. Toggling it leaves the toolbar anchor unchanged.
- Interaction Lab includes **Use one-line text toolbar**, enabled by default. During active label editing and immediately after selecting a text object, Grouped replaces the object row with Flat's explicit font, size, emphasis, text color, and alignment controls. Back from a text object reveals its whole-object row. Switching the modifier off restores Grouped's automatic Text popover. Manually opening Text from the Grouped object row remains a popover in either setting. This preference saves locally and travels with experiment JSON.
- Interaction Lab includes **Show more actions**, disabled by default. Enabling it appends a vertical three-dot button to the end of every formatting row in all three solutions. Its connected menu holds uncommon operations: Set default style, Copy style, and Paste style. Default styles apply to new objects of the same kind for the current session; the style clipboard is also session-scoped. Mixed formatting disables Copy, and mixed object kinds or formatting disable Set default. The visibility preference saves locally and travels with experiment JSON. Opening or closing the menu never moves the toolbar.
- Interaction Lab includes **Show toolbar shortcuts**, disabled by default. Enabling it adds small V/B/L/T/R/O hints to the corresponding canvas tool buttons without changing their size. Tooltips always include shortcuts whether or not these hints are shown. The visibility preference saves locally and travels with experiment JSON.
- Mixed selections expose only shared capabilities. Compound summaries explicitly show Mixed when relevant values differ.
- Only one compound group is open. In Inline, a simple color dropdown can coexist with the expanded group; closing the dropdown preserves that group.
- Sticky groups remain open across compatible selections when enabled. A port cannot retain a Stroke group; a connection cannot retain Alignment.
- Place the toolbar using its own dimensions: above the selection when it fits, otherwise below. Opening, switching, or closing a popover never changes the toolbar's position. Popovers prefer the outward direction (upward for a toolbar above the selection, downward for one below). When there is insufficient outward space, flip only the popover to the opposite side of the toolbar; covering the selection is allowed in this edge case. Popovers may shift horizontally to stay within the viewport, align to their originating button, and retain a small visual connector.
- When neither side can fit the toolbar, including oversized selections, dock it at a viewport edge. If a popover cannot fit in either direction, cap its height to the available space and scroll its contents so controls remain reachable. Long Inline rows scroll horizontally instead of turning into stacked detail panels.
- Underline, strikethrough and top/middle/bottom alignment were added because they appear in the reference controls. Alignment is omitted for connection and port labels whose position follows geometry.
- The user's latest correction replaces direction toggle/reverse with two controls in all three solutions: an arrow-style group and a separate iterator button. Arrow selection follows the active behavior: Flat replaces the row with four icon buttons and Back, Grouped opens a connected popover with those buttons, and Inline expands them in the row. Both uses a single bidirectional arrow icon; the iterator uses a distinct iteration icon. The current choice is highlighted; choices stay open for experimentation and the iterator remains separate. The iterator cycles None → Left → Right → Both → None. Left means the path's source end and right its target end. Endpoints stay attached. Arrowheads scale with 1, 2, 4, and 8 px strokes so they remain visible at larger widths. Start and end triangles stay on the original attachment path. A separate visible shaft stops at each triangle base, so thick strokes cannot protrude through the tip. Rounded patterned caps are retained only when they fit inside the triangle. Arrow depths shrink to fit short terminal segments, and zero-length routes omit arrowheads. Mixed selections start at None, then cycle together; each click is one undoable edit. Legacy directional/reversed fields remain readable, and new optional `arrowStyle` values persist in version 2 snapshots.

The default custom palette starts with four colors observed on [Octopart](https://octopart.com/) on 2026-09-12: blue `#0A70CF`, charcoal `#303336`, pale blue `#E8F3FE`, and white `#FFFFFF`. The revised palette uses a new browser-storage key to replace the old row of accidental intermediate shades; the old key is retained as a recoverable backup. New additions save on the native color dialog's committed change, not on drag-preview input events. Stored swatches are normalized and deduplicated, with the most recent eight retained.

The Interaction Lab contains the scene selector, behavior choices, five display and formatting modifiers, the compatible-selection preference, and Reset scene. The Current context block and Try it instructions have been removed. With one editable object selected and canvas focus, typing immediately replaces its label; Enter/F2 or double-click edits the existing label. Each solution reveals its text controls automatically. Enter commits; Escape closes the innermost popup before cancelling a draft or leaving a formatting sub-toolbar. Whole-label Ctrl/Cmd+B/I/U formatting also works without entering content editing. The [keyboard shortcut scheme](shortcuts-proposal.md) is shared across all three solutions, with tool letters limited to an empty selection. Focused controls retain their normal keys except for Ctrl/Cmd+/, which opens the app-wide searchable command palette.

## Persistence

Version 2 snapshots use `flat`, `grouped`, and `inline`. Version 1 JSON and browser storage migrate without resetting the diagram: `replace` → `flat`, `stack` → `grouped`, `inline` → `inline`. Missing new text properties receive neutral defaults.

## Comparison tasks

Use the same diagram and selection in every solution. Compare how quickly users find a property, whether its current state is visible, how much the toolbar grows, and whether they lose the selected object while opening a group. See `experiments.md` for the task list.
